PROBLEM 01
Entity Disambiguation & Confidence-Based UX
When AI isn't sure, how much should it involve the human?

When a user searches "Show me contracts with Johnson," the system finds 4 matching entities. The design question isn't "show a list" — it's "what level of human involvement does this ambiguity require?"

I designed a three-stage disambiguation system: Prevention (autocomplete and smart chips stop ambiguity before submission), Interpretation (the NL parser ranks interpretations by confidence and executes the top one immediately), and Recovery (alternate interpretations shown passively after results).

PROBLEM 02
Self-Improving Learning Loops
A disambiguation system that progressively makes itself redundant.

The disambiguation cards aren't permanent UI. They're a temporary preference collection mechanism that makes itself redundant as adoption grows.

I designed four learning parameters that compound over time:

User preference score — logs term→field selections per user. After 3 consistent picks, the card suppresses silently. Org pattern score — aggregates tenant-level behavior, solving cold start for new users. Recency weight — full authority for last 30 days, tapering to 40% beyond 90 days. Staleness decay — when new schema fields are added, preferences mapped to old fields decay, allowing cards to temporarily resurface.

The compounding effect: the more users engage with disambiguation, the less they see it. The system gets smarter from every interaction without explicit training.

PROBLEM 03
Agentic Context Management
Keeping conversation and workspace in sync across scope changes.

AskSirion uses a bi-directional context sync between a conversation panel and a workspace panel. The north star rule: "Conversation context must always match what is visible on the workspace."

I designed navigation as a browser history stack — Listing → Contract → Document — with context syncing back. Follow-up queries resolve against the filtered context, not the global query. Dismissing a disambiguation card mid-conversation creates a stacked state with independent dismissibility. The workspace panel holds previous results rather than going blank.

PROBLEM 04
Chain of Reasoning & Trust Architecture
Showing AI's work so enterprise users trust the output.

Enterprise users — legal teams, compliance officers — need to audit what the AI did, not just see the answer. I designed a three-step chain of reasoning that shows real intermediate outputs.

The principle: only show steps that produce a genuine intermediate result the user could verify. Never fake progress spinners. Each step shows what was detected, what confidence was scored, how many records matched. The "2 Steps" COT pill communicates reasoning depth without theatre. For legal and procurement teams doing compliance audits, this transparency is the difference between trust and rejection.

Explainability Chain of Thought UX Enterprise Trust
PROBLEM 05
Prompt Discovery & Question Literacy
Users don't know what AI can answer — so they don't ask.

I diagnosed the core AI usability problem: users think in intents, not field names. They don't know "Liability Cap" is queryable, so they either ask the wrong things or don't engage at all. The fix isn't better help text — it's a recognition-over-recall discovery system.

I designed a prompt library with field highlighting inside prompt sentences — users learn what's queryable by reading natural-language examples, not a field list. Category tags (Risk, Governance, Renewals, Finance) double as navigational triggers that open the library filtered to that domain.

The north star test: "How many questions does the user think the system can answer?" The taxonomy architecture serves admin-configured prompts, frequency-based surfacing, persona-based grouping, and metadata-driven recommendations — all without exposing that machinery to the user.

Recognition over Recall Question Literacy AI Discoverability
PROBLEM 06
Search Expansion Control & User Agency
When should AI expand a query vs. match exactly? Let the user decide.

Searching "Microsoft" returns results for MSFT, Microsoft Corporation, and Microsoft Inc. Great for exploration. Dangerous for compliance audits. I designed the Search Style selector — Expanded (default) vs. Exact Match — giving users persistent, explicit control over AI query expansion.

I pushed back on the PRD's mid-session lock requirement. The argument: removing user agency at the moment they most need it — after seeing unexpected results — is a UX failure, not a safeguard. The lock would generate support tickets for stuck-feeling users with zero product value. I mapped every PRD requirement against UX position with explicit alignment status, getting 3 items flagged for resolution before handoff.

Query Expansion UX PRD Negotiation User Agency
PROBLEM 07
Hybrid AI + Traditional UI
Making AI feel like a collaborator, not a replacement for structured search.

Enterprise users need both: the efficiency of AI answers AND the control of manual search. I designed the interaction model where GenAI conversational search and cognitive (faceted) search coexist — with smooth fallbacks between them.

The response structure blends AI-generated summaries, structured data views (tables, charts, filter chips), and suggested follow-ups. Each conversational turn can shift between natural language insights and drill-down into structured data. The right panel workspace syncs with conversation context — filtering results, opening a contract, or changing the canvas all maintain the bi-directional link.

I also designed six distinct AI interaction patterns used across the product: command input, inline assist, contextual selection, proactive surfaces, agentic progress tracking, and structured AI output. Each pattern has defined use cases and failure modes.

PROBLEM 08
Agentic Action Design (Agent OS)
When AI doesn't just answer — it acts. On contracts.

AskSirion is shipping inside Agent OS — an in-house agentic platform where agents perform actions: contract creation, clause deviation, redlining, parent-child mapping. This shifts the user's role from navigator/interrogator to initiator of consequential actions.

In an agentic context, disambiguation has higher stakes — an agent acting on a misinterpreted query could trigger a workflow on the wrong contracts. The card copy shifts from "which field should I search" to "which contracts should I act on." I'm designing the distinction between informational responses and action outcomes, how system-initiated messages land in conversation without breaking the "I ask, it answers" mental model, and how agents across the Store/Create/Act taxonomy surface their capabilities.

02 — DESIGN SYSTEM VIA AI

I work as an agentic AI designer on Project HALO — Sirion's UX 3.0 platform redesign. The system is architected in partnership with AI co-pilots, audited end-to-end for WCAG 2.2 AA, and shipped as a fully tokenized, Figma MCP–ready library that designers, developers, and Claude agents all consume from the same source. Token authored once. Translated never.

PHASE 0
Three-Tier Token Architecture
Primitives → Semantics → Component tokens. 4 Figma Variable collections with light + dark modes, mirroring MUI / Devias structure so designers and engineers speak the same language from line one.
PHASE 1
Designer-Authored Components
Button shipped as POC — 60 variants × 4 states × 3 sizes, every fill, stroke and text bound to variables. Input, Table, Card, Modal, Nav, Chip next — each carrying a prop manifest agents can read.
PHASE 2
AI-Native Surface Library
Answer cards, prompt input, COT pills, disambiguation cards, trust badges, fallback states — the AI-specific component set most design systems don't have, reused across AskSirion and Agent OS.
PHASE 3
WCAG 2.2 AA + Figma MCP Bridge
Every token contrast-paired and audited to WCAG 2.2 AA. Figma connected to Claude via MCP — agents read components, generate MUI code against theme.vars.*, flag drift across Figma and codebase. No hardcoded hex.

The pipeline is the product: Figma Variables → Tokens Studio → tokens.json (Git) → Style Dictionary → Devias theme. Designer authors once. Code consumes forever. A Claude agent bridges both sides — generating a new HALO screen from the same source designers maintain: architecturally aligned, token-faithful, and WCAG-clean by default. I didn't just design the components — I designed the interface the agents use to work with them.
